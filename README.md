# Product LingLing（灵灵）

AI 产品机会分析工具 — 把行业信号自动转化为可验证、可行动的产品机会。

## 它做什么

每天 08:30 自动抓取 AI HOT 精选 RSS（约 50 条行业信号），全量增量存储，通过信号评分 + 关键词聚类生成两张产品机会卡：

| 类型 | 标签 | 策略 |
|------|------|------|
| ◎ 相关洞察 | 同领域高信号条目 | 按信号质量评分选最优簇，取该簇最佳条目分析 |
| ⚡ 跨界创新 | 距离最远的两个领域各取一条 | 簇间距离矩阵最大化碰撞感 |

每张卡包含：

- **判断层**：用户画像、痛点、AI 解法、MVP 方案、6 维可解释评分（满分 10）、主要风险、下一步验证、原文信息源链接
- **行动层**：动手前体检（先准备什么 / 第一个可验证里程碑 / 证伪信号）+ **开工提示词**——一段可直接复制给 Claude/DeepSeek 的完整「验证 SOP」（桌面调研 → 痛点证伪 → 最小验证物 → 明确结论），由确定性模板拼装，老卡自动降级生成

> 评分约定：`competition` 维度为反向编码（分高 = 竞争小），全链路正向加权。

## 界面（三个版本并存）

| 版本 | 定位 | 入口 |
|------|------|------|
| **v3「每日开卡」** | 主版本。浅色刊物风 + 开卡仪式，移动端/桌面端响应式 | `/`（自动跳转）或 `/v3.html` |
| v2「空间纵深」 | 桌面端基线。前景机会 / 后景信号星图，3D 穿层 | `/v2.html` |
| v1 原型 | 稳定备份 | `/prototype.html` |

### v3 核心体验

- **开卡仪式**：今日双卡以卡背呈现（卡背印当期种子纹理），点按翻牌 → 评分滚动揭晓 → 跨界卡两领域词飞入相撞；双卡翻开出现碰撞连线与动态注释；当日翻牌状态记忆，次日重置
- **种子生成视觉**：以当日信号聚类分布为种子，生成每期专属的刊头纹样与卡背图案，永不重复
- **数据彩蛋**：8.5+ 稀有卡闪光、「本月最强碰撞」徽标、连续打卡天数、机会库 50/100/200 里程碑
- **✦ 适合我**：气泡选择器（身份/投入/目标）按 6 维评分加权重排机会库，出 Top 3 + 匹配理由（偏好本地记忆）
- **▲ 本周 TOP**：近 7 天机会卡按评分策展 Top 5
- **机会签**：每张卡一键生成 800×1000 分享图（Canvas，含种子纹理与评分大字）
- **无障碍**：prefers-reduced-motion 全套降级、键盘翻牌、触控目标 ≥44px

## 技术栈

| 层级 | 技术 |
|------|------|
| 前端 | 单文件 HTML ×3（v3 响应式 / v2 桌面 3D / v1 原型），零框架零依赖 |
| 后端 | FastAPI (Python) |
| 数据库 | SQLite（自动迁移） |
| 大模型 | DeepSeek API（相关/跨界双 Prompt + kickoff 结构化槽位） |
| 定时任务 | APScheduler（每日 08:30 CST） |
| 部署 | Nginx + uvicorn + systemd |

## 快速开始

```bash
# 1. 克隆项目
git clone https://github.com/LLing486/product-lingling.git
cd product-lingling

# 2. 配置环境变量
cp .env.example .env
# 编辑 .env，填入 DeepSeek API Key（LING_DEEPSEEK_API）

# 3. 启动后端
pip install -r backend/requirements.txt
uvicorn backend.main:app --reload

# 4. 访问 http://localhost:8000 （自动进入 v3）
```

无后端时直接双击打开 `frontend/v3.html`（或 v2.html）即进入演示模式（内置 Mock 数据）。

## API 端点

| 端点 | 说明 |
|------|------|
| `GET /health` | 健康检查 |
| `GET /api/cards` | 机会卡列表（支持 keyword / direction / date 筛选） |
| `GET /api/cards/today` | 今日机会卡（无数据时回退到最近一天） |
| `GET /api/cards/{id}` | 单卡详情（含 kickoff / kickoff_prompt 字段） |
| `POST /api/cards/generate` | 手动触发生成（仅 development 模式） |
| `GET /api/sources` | 全部 RSS 条目 |

## 创新方向储备（功能广度候选）

> 原则：沿「信号 → 分析 → 判断 → 行动 → 反馈」价值链延伸，不横向堆功能。
> 优先级：1 > 2+3 > 4，其余为放大器。记录于 2026-07-03。

| # | 方向 | 一句话 | 要命的假设 | 最便宜的验证 |
|---|------|--------|-----------|-------------|
| 1 | 预测开卡 | 翻牌前先押注（猜哪张分高/评分区间），积累「你的判断 vs AI」曲线，把读判断变成练判断 | 用户愿意在看答案前动脑 | V3 加可跳过的押注步骤，看跳过率 |
| 2 | 命中回访 | 90 天后自动重扫信号源，给历史卡打「命中/证伪/未决」，机会库变成有胜率的判断记录 | 信号源足以判定命中 | 人工回访 10 张 90 天前的老卡试判定 |
| 3 | 机会持仓 | 用户 watchlist 机会方向，新信号自动关联推送「你关注的方向今天有 N 条新信号」 | 用户会持续关注特定方向 | 前端加收藏按钮看使用率 |
| 4 | BYOS | 用户丢链接/想法进来，用同一套 6 维评分引擎出卡；从每日推送变随时可用的判断引擎 | 用户有自己的信号要分析 | 假门按钮「分析我的链接」看点击率 |
| 5 | 异构信号交叉验证 | 加代码信号（GitHub 增速）、资本信号（融资）、人才信号（招聘），同方向共振时评分加成 | 异构信号可靠可得 | 手动给 5 张卡补三类信号看增益 |
| 6 | 对话式卡片 | 每张卡可追问（「MVP 改 toB 会怎样？」），开工提示词的产品内化 | 追问频率足够高 | 详情页加假门「继续追问」 |
| 7 | 反向选项：做减法 | 每日 2 张改每周 1 张深度精选+完整调研报告 | 用户消化不完每日产出 | 周榜打开率 vs 每日打开率对比 |

三者接力：预测开卡是**习惯引擎**（每天回来）→ 命中回访+持仓是**信任引擎**（长期相信）→ BYOS 是**增长引擎**（主动使用）。
